Document Q&A that never leaves your machine

JJRAG is a complete data pipeline — extraction, transformation, validation, loading, retrieval and answering — for asking questions of your own documents. Every stage runs on hardware you control. There is no hosted model API in the codebase, and the runtime blocks outbound connections to prove it.

Why local, specifically

Sending a document to a hosted model means a third party receives its contents, logs the request, and holds it under their retention policy rather than yours. For regulated data — customer records, health information, legal files, anything under a data-processing agreement that does not name that provider — that is usually the end of the conversation.

JJRAG removes the question rather than answering it. Generation runs on Ollama on your host; embeddings run locally through sentence-transformers; and the process installs a socket-level guard that refuses any connection outside loopback and your configured model host. A dependency that tries to phone home raises an error instead of succeeding quietly.

Validated, not just loaded

Twenty-plus rules gate the run: empty extractions, garbled text, oversized chunks, zero vectors, dimensionality drift, index/catalog parity. A breach fails the run instead of publishing a broken index.

Atomic index versions

Each run builds a new index beside the live one and only flips the pointer after every gate passes. A failed ingest cannot take your working index down, and rollback is one command.

PII redacted before storage

Emails, phones, national IDs, card numbers, IBANs, IP addresses and API keys are replaced with typed placeholders before anything is indexed — then re-checked, so a leak fails the run.

Auditable end to end

Every run writes a manifest: what was admitted, rejected, redacted, checked and published. Every privileged action lands in an append-only audit log. Both are queryable from the API.

Answers with citations

Hybrid retrieval (semantic + keyword, fused) feeds a local model that is instructed to cite excerpt numbers. When nothing relevant is found, it says so rather than inventing an answer.

Erasure that actually erases

Deleting a document removes it from the catalog and rebuilds the index without it — the deletion reaches the vectors, not just a list.

Quick start

git clone https://github.com/jfjustin/JJRAG.git
cd JJRAG
pip install -r requirements.txt

# Install a local model (once)
curl -fsSL https://ollama.com/install.sh | sh
ollama pull llama3.1:8b

# Check the environment, then load documents
jjrag doctor
jjrag ingest ~/Documents/policies

# Ask, from the terminal or the browser
jjrag query "What is our data retention period?"
jjrag serve            # → http://localhost:8000

Prefer containers? docker compose -f deploy/docker-compose.yml up -d brings up the app and the model on an internal-only Docker network with no route to the internet. See Hosting to publish it on your own domain.

What it reads

PDF (with page-level citations and an optional OCR fallback), DOCX, PPTX, TXT, Markdown, HTML, CSV/TSV, JSON/JSONL and EML. Tabular and structured formats are serialised so that each chunk stays self-describing — a CSV row keeps its column names, an email keeps its headers — which is what makes them retrievable at all.
